# PDF 表格视觉审计基线

本基线用于评估解析器，不参与生产规则。生产代码不得读取文档名、页码或下列样本标签；这些信息只允许用于回归和误差分析。

## 口径

- 审计日期：2026-08-23。
- 对三份 PDF 的全部 267 页逐页查看，同时逐张复核轻量版面模型标为 `table`、但未能结构化的 86 个 snapshot 候选。
- 一个边界连续、语义上独立的二维表格区域计为一张表。目录、寄存器位示意、流程/时序/封装线框图和代码块不计为表格。
- `table snapshot candidate` 只是模型标签，不等于真实表格；视觉确认结果才是本测试集的评估真值。
- M8P6272 第 54 页发现一张候选模型完全漏掉的紧凑表。通用补提规则修复后，它已计入结构化表数量。

## 无边框嵌套子表审计

对最终 274 张结构化表逐格读取 PDF 原生物理行，枚举“同一 outer row 中所有列行数相同且基线对齐”的候选。生产判定不使用文档名、页码、章节标题词义或字段词表，还要求至少半数列的行宽明显小于 cell 宽度，并在相邻正文行中重复出现；row 0 始终作为表头保留。

六个实际引脚说明表的 38 个 outer row 已逐页与原 PDF 纵向位置核对；150 条 `semantic_rows` 均保持“名称/类型/说明”逐基线对应。JSON 同时保留 outer `rows/cells` 与规范化语义视图，`row_provenance` 可回溯到每列的原生 block/line ID 和 bbox。Markdown 只渲染规范化视图，从源头避免 chunk 阶段重复推断父行和子行。

## 视觉区域补提与裁剪

- 对 267 页的原生向量组件与既有 TABLE/VISUAL anchor 做覆盖审计，发现两处模型完全漏掉的独立向量图：M8P5170 第 7 页第一张引脚图，以及 M9F6820 第 72 页第二张时序图；两处均已由同一通用规则补回。
- 引脚图、曲线图和封装图的截图边界不再直接使用模型 bbox，而是联合原生 drawing/image、同带文字和相邻 anchor 校正。
- 并排或上下排列的图以相邻 anchor 中线隔离；已有正文和 figure title 保持独立文本，防止扩框吞入上下文。
- 上述漏图页、三张 M8P5170 引脚图、其余引脚图和最大扩框比例样本均做了最终 PNG 视觉复核。
