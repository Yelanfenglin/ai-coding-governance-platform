# RAG 链路经验

> 本文件汇集 RAG 链路各阶段的问题、根因与解决方案，是全链路的经验库。
> 当前只有第一阶段 **文档解析经验**（针对 M8P5170 / M8P6272 / M9F6820 共 267 页规格书）；
> 后续 chunking、向量化、检索与问答阶段的经验将陆续以新章节补进本文件，
> 同类问题再次出现时先查这里。

## 文档解析经验

### 0. 核心经验（先读这三条）

1. **弱模型只给候选，不给真值。** 轻量 layout 模型的 `table`/`image` 标签误判率很高
   （86 个 table 候选中只有 50 张真表）。任何“是表/是图”的最终判定都要靠几何结构，
   模型 label 只用于锚定区域与阅读顺序；真值以人工视觉审计为准。
2. **宁可不合并，也不要错合并；宁可不升级，也不要错升级。** 所有一步到位重建
   （rowspan/colspan、跨页拼接、子表拆行、标题建树）都以“证据不足就回退”为前提，
   并用**冻结已稳定的分类**来保证修一处不崩另一处。
3. **生产规则禁用词表。** 文档名、页码、章节标题词义、`IOA/PWM/TK/Option` 等芯片字段
   永远不能进判定逻辑；它们只出现在回归断言里。这样规则才能在别的芯片文档上复用。

### 1. 版面与阅读顺序

### 1.1 双栏阅读顺序左右互串
- **现象**：PP-DocLayout 对双栏页的文字顺序经常左右栏交替，导致内容读起来串行。
- **根因**：模型按视觉块输出顺序，双栏页的“块顺序”不可靠。
- **方案**：不重新分块，只做保守的阅读顺序修复；检测到“窄文本形成两个横向明显分离、
  纵向重叠的簇”（≥每个栏 4 个块、横向间距 ≥15% 页宽）时才启用“band 分隔 + 左到底再右到底”；证据不足完全退回 PP order。
- **原则**：顺序是后处理，分块不动；没有强证据不要重排。

### 1.2 页眉页脚/页码进正文
- **现象**：正文里混入页码、页眉网址等噪声。
- **方案**：layout 的 header/footer/number 直接映射为 NOISE 排他 owner，不进入正文；
  再加“未命中任何广告”的 auto 行兜底，保证每条原生行都有唯一归属。
- **原则**：排他 ownership 优先于“要不要这行”。

### 2. 表格

### 2.1 rowspan/colspan 推断“吞整列”
- **现象**：BANK 表变成 `<td rowspan="19">BANK0 BANK1 … BANK15</td>`，
  封装表首列变成 `<td rowspan="12">A A1 A2 b D…</td>`；整列文字被错误纵向合并。
- **根因**：缺 separator 的相邻原子格被合并，而旧规则没有检测“合并区内每个原子行
  都有自己的文字”这一强反例。
- **方案**：先恢复细填充矩形边线（0.5–2pt）与共线分段 rule；再按“原子文字锚点”分段：
  合并区内若多个原子行/列各自有文字 → 拆回独立 cell；只有文字集中在一个原子区才保留
  merge。拆分的兜底阈值：≥3 行/列高密度记录 + 邻接 separator 多数支持，
  且**行/列文字覆盖至少一半 span** 才允许拆，防止竖排分组标题被拆碎。
- **验证**：BANK0/BANK15 真实两行合并保留，BANK1–BANK14 逐行；
  封装符号列逐项恢复；指令表 29/34 行真实分组标题保留。
- **原则**：几何（separator）优先，文字只是反例证据；两行歧义、多行表头、纵排标签一律保守。

### 2.2 表格与快照分类误判
- **现象**：封装图、波形图、代码块被轻量模型标成 `table`（36 张误标）；
  真表格也有漏检；还有一张 3×2 小表完全没框。
- **方案**：以人工视觉逐页审计为**权威基线**（86 候选 → 50 真表 + 36 误标 + 1 漏检）；
  代码只做“分类冻结 + 失败升级 + 漏检补提”，不让增强几何去改写已冻结的分类。
  漏表补提要求“重复二维记录 + 邻近标题/正文/已有表格上下文”同时成立，
  不要求固定词汇（如 `BitN`）出现。
- **原则**：模型分数≠真值；人工审计建立基线；修分类要“冻结旧分类，新增/升级走独立通道”。

### 2.3 无边框嵌套子表（一个格子里的多行）
- **现象**：`IOA[2] TK2 PWM02 CP VREF` 一行其实是“没有画横线的子表”，
  压平后丢失 `CP ↔ A ↔ LVD 外部电压输入口` 的映射关系。
- **方案**：解析层一次性判定：多个相邻正文行在所有列中**物理行数相同**、跨列基线对齐、
  行宽留白充分、且该模式在相邻行**重复出现**时，生成规范化 `semantic_rows / aligned_subrows`；
  否则回退（两行表头、普通折行、单个多行 cell 都不拆）。
- **为什么在解析层做**：结构信息在解析阶段最完整；若留给 chunk 层二次推断，
  会同时保留平铺行 + 父子 chunk，重复召回且难防误拆。
- **原则**：结构判定要一次性做在最接近真值的地方，且不引入词表。

### 2.4 多视觉单元格编码为一个 text span
- **现象**：PDF 生成器把一个 span 的字符跨多个 cell 编码，整 span “中心归属”
  导致一列 label 全进同一个 cell（IOAICR / MPPWM1 / PWM1CR 等寄存器位表）。
- **方案**：span 保留**字符级 bbox**；字符按坐标落入哪个 atomic cell 就分配到哪里；
  仅当字符分组对应多个不同 cell origin 时才拆格，真实 rowspan/colspan 共享 origin 不拆。
- **效果**：文档内 8 个 span、29 个 cell 文字归属被恢复，表拓扑零变化。
- **原则**：整 span 的中心/文本不可靠时，退化到“字符”这一最细粒度证据，
  但只在有多个不同归属时才动用。

### 2.5 跨页表格被页边界切断
- **现象**：下一页重复表头继续上一张表（直流特性 64→65、引脚表 9→10、
  序号表 135→136、引线 11→12→13 等多页链）。
- **方案**：物理拼接，四条件：前一页最后 block 是表 + **下一页第一个 body block 就是表**
  + 表头取最长相同行前缀（去空白归一化，兼容 `单位`/`单 位`）+ 列数与水平 span 一致。
  输出 `<!-- pdf-pages: N-M -->` 与 `source_pages`。
- **关键反例**：相邻页大量 `Bit7..Bit0` 表头相同，但下一页有真章节标题 → 不满足
  “第一个 body block 是表”，绝不合并。
- **明确不做**：rowspan/单元格被页切断、表格截图跨页。
- **原则**：表头相同 ≠ 是续表；页边界做“首 block 检查”比任何评分都稳。

### 3. 图片

### 3.1 引脚图被裁边 / 整体漏检
- **现象**：截图 bbox 只包住芯片主体，左右引脚标签被裁；M8P5170 的 SOT23-6
  纯矢量图被模型完全漏检，被拆成十几行正文。
- **方案**：模型定位 + 原生图元/同带标签扩框；并排图以相邻 anchor 中点二维分界；
  已识别正文/图题 anchor 构成硬边界（不吞正文）。纯矢量漏图要求
  “连通组件 + 二维尺寸 + 局部文字密度 + 不重叠”才补提。
- **原则**：扩边界的证据是原生图元与相邻关系，不是按图题词表猜。

### 3.2 保留截图而不是强行文字化
- **决策**：复杂芯片图、时序图、封装图保留截图 + `annotations`（图内原生文字），
  `<!-- annotations: … -->` 提供搜索信息。机器至少知道“这里有图”。
- **原则**：无法可靠结构化的区域，保真截图优于错结构化。

### 4. 标题与正文

### 4.1 标题层级没建立、枚举值被误升
- **现象**：`1` 与 `1.1` 都是 `##`；`2.2.3 系统寄存器定义` 漏判；
  `0 = 关闭`、`8 位模式` 被误升 H2；`注：` 备注框被当作标题。
- **方案**：全文语境下五类证据打分（布局标签、相对字号、已接受层级、
  同级编号/根编号序列、邻近子标题），`1→H2`、`1.1→H3`…
  短标题需要第三项证据；负向前缀与枚举值直接否决。
- **原则**：单条正则只做候选，上下文打分做决定；裸数字必须有版面/序列支持。

### 4.2 正文硬换行
- **现象**：`可用于系\n统时钟` 等 PDF 视觉折行残留。
- **方案**：同一 text block 内合并：上一行不是句末标点、下一行不是 bullet/标题/新结构
  才拼接；中文直接连、英文按字符补空格。
- **原则**：只做块内合并，绝不跨块；目录区域整体豁免（见 4.3）。

### 4.3 目录项被合成一行
- **现象**：`应用注意事项 ... 5 1 产品简述 ... 6`——根级目录项被拼进上一行。
- **根因**：根级目录 `1 产品简述` 不是 bullet（无 `.`/`、`）也不以句末标点结尾，
  普通 reflow 判定“应拼接”。
- **方案**：TOC 页检测（`目录` 标题或 ≥5 条点线+末尾页码行）→ 停止段落重排，
  按视觉基线一行一项；**末尾页码=硬闭合**；长标题折行仅在前一行无页码、下一行带页码时拼接。
- **原则**：不同内容的最基本结构不同——目录是“一行一项”，不是“一段”。

### 5. 流程与工程

### 5.1 先出原型后合并、回归要可量化
- 所有大改动（先修 rowspan → 再修分类 → 再修跨页/目录）都先在隔离副本实现 +
  单测通过，再同步主仓库；每步都对比“修了多少、有没有误伤”（基线计数、逐页 A/B）。
- 真实 PDF 回归全部走 `RAG_PARSER_*_FIXTURE_*` 环境变量，普通 `pytest` 不依赖私有文件。

### 5.2 审计器与不变量
- `audit_reconstruction.py` 检查：summary/页数一致、0 orphan、0 duplicate ownership、
  0 missing snapshot、表格矩阵形状、cell 全覆盖且不重叠、语义行 provenance 一致性、
  标题树层级、`pdf-page`/`pdf-pages` 标记完整性、图片引用可解析。
- 跨页拼接后审计器也感知：统计随 owner 页迁移；被整页吸收的空页允许无独立标记。

### 5.3 分层清单（什么属于哪一层）
- **解析层**：保留几何事实（行/span/字符 bbox、outer topology、逐行来源）；
  一次性完成结构判定（子表、跨页、目录）并输出规范化视图。
- **chunk 层**：消费 `source_pages`、`semantic_rows`、`section_path`，不再二次猜测
  表格结构。
- **检索层**：父行/子项都携带表头、章节、页码与父行引用。

### 6. 一句话对策速查

| 症状 | 对策 |
|---|---|
| 表格整列被合并 | 拆候选 merge：原子文字锚点多行/多列则分段；≥3 行高密度+邻接 separator 支持才兜底 |
| 到底是表还是图 | 人工视觉审计定真值；模型 label 只当候选；分类冻结，修复走升级通道 |
| 一个 span 穿多个 cell | 字符级 bbox 按 origin 分配；同一 origin（真 rowspan/colspan）不拆 |
| 跨页重复表头 | 首个 body block 是表 + 表头归一化一致 + 列结构一致才拼接；先检查再评分 |
| 目录被合并 | 目录模式：一行一项，末尾页码硬闭合 |
| 引脚图被裁/漏检 | 模型盒 + 原生图元/邻图分界/正文硬边界；矢量漏图多条件补提 |
| `0 = 关闭` 变标题 | 多证据打分；裸数字、负向前缀、枚举值拒绝 |
| 编号层级乱 | `1→H2`、`1.1→H3`… 由章节序列与近邻子标题建立 |
